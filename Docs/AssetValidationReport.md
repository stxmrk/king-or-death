# KING OR DEATH — Asset Pack 001

Дата проверки: 28 ноября 2026. Ветка: `feature/asset-pack-001`.

Созданы и подключены шесть редактируемых 3D-ассетов. Техническая интеграция работает, но художественная готовность всего комплекта пока **Needs Improvement**. Это первая библиотека для дальнейшей доработки, а не финальный набор уровня приложенных референсов. Расширение библиотеки не выполнялось в ущерб проверке этих шести моделей.

## Материалы и масштаб

14 общих процедурных PBR-материалов; 90 PNG по 1024×1024. Для каждого материала есть Base Color, Normal, Metallic, Roughness, нейтральный AO и упакованный Metallic/Smoothness для URP. Дополнительно запечены шесть уникальных AO для основных мешей. У отдельных оружия, колёс и флага используется общий нейтральный AO, не индивидуальная запеканка.

В Base Color нет запечённых теней. UV автоматически развёрнуты; единая плотность texel и ручная раскладка швов не доведены до финального качества. Материалы общие, но уникальный AO создаёт варианты материалов для отдельных моделей; это не гарантирует минимальное число draw calls. Атласирование и профилирование большого сражения остаются задачами оптимизации.

Человек около 1,8 м; волк около 0,8 м в холке. Источники используют метры. У Unity-префабов нейтральные корни с масштабом 1; преобразование осей FBX сохранено внутри. Pivot зданий у основания, колес — на осях. Коллайдеры простые, без MeshCollider.

## Анимации

Исходная частота 30 FPS; 19 отдельных сохранённых Actions и импортированных клипов:

- Мечник: Idle, Walk, Run, Attack_01, Attack_02, Hit, Die.
- Рабочий: Idle, Walk, Carry, ChopWood, PickUp, Die.
- Волк: Idle, Walk, Run, Stalk, Attack, Die.

Все состояния контроллеров найдены при запуске. Для 16 не-Idle состояний проверено изменение skinned-геометрии; Idle проверен на наличие состояния. Это подтверждает подключение анимации, но не художественную готовность движений. Скользящие стопы, жёсткие суставы и упрощённые атаки остаются. Humanoid для людей не настроен и совместимость аватара не подтверждена; сейчас все три рига Generic. Root motion отключён, перемещение выполняет существующий UnitMotor.

После смерти игровая модель сохраняется в замороженной позе Die; сохраняются система останков, запах, захоронение и перенос. Цвет ткани противника задаётся бордовым материалом и сохраняется у тела. Это временное использование модели мечника для противников; отдельный Raider не создан.

Среда: Windows, Blender 4.2.1 LTS, Unity 6000.6.10f1, URP 17.6.0. Unity 6.6 — установленная версия, не LTS. Импорт в другие версии не проверялся.

- Blender: сохранение и повторное открытие шести исходников, аудит всех LOD и весов, экспорт FBX, рендеры Cycles.
- Unity Editor: импорт всех FBX, настройка URP, сохранение префабов, рендеры шести моделей и сборка двух Windows x64 приложений без ошибок компиляции.

- Игровой standalone, `Prototype_01`: **29 PASS** — исходные игровые проверки и дополнительные проверки новых моделей, колёс, флага и лежащего тела.
- Проверены выделение рамкой, обход реки через мост, захват и оспаривание поста, строительство, физическая добыча и перевозка, ожидание пустого склада, бой, смерть, реакция волков, уборка тел, перезахват, остановка маршрута и salvage обоза.

Логи проверок: `Docs/AssetRuntimeValidation.txt`, `Docs/ArtIntegrationValidation.txt`. Кадры получены непосредственно камерой Unity в работающем Editor/standalone через RenderTexture. Автоматический standalone-тест не равнозначен ручной проверке всех кнопок в окне Editor Play Mode; такая полная ручная проверка в этой итерации не выполнена.

Производительность: 60 анимированных мечников, автоматические LOD, 1600×900, NVIDIA GeForce RTX 2060, **148,9 кадра/с** за 5 секунд. Камера рендерилась явно каждый кадр, после чего выполнялось синхронное чтение одного пикселя GPU. Время включает эту синхронизацию и исключает боевой ИИ/поиск пути. Это отдельный тест отображения моделей, не Unity Profiler и не FPS обычного окна игры. Первоначальный результат скрытого окна без принудительного рендера отброшен как недостоверный. Сотни юнитов, долгие партии и накопление сотен тел пока не измерены.

## Воспроизведение конвейера

Скрипты находятся в `ArtSource/Tools`. В копии проекта последовательно выполнить Blender `-b --python ArtSource/Tools/asset_production.py -- <project> <phase>` с фазами `all`, `refine_wolf`, `refine_post`, `repair_animations`. Последняя фаза сохраняет все Actions как fake users и пересоздаёт экспорт клипов. Затем `audit_sources.py` и `render_sources.py` с аргументом `-- <project>`.

В Unity выполнить `KingOrDeath.Editor.ArtPackImporter.BuildAll` через `-executeMethod`: метод импортирует модели, пересоздаёт витрину, сохраняет интеграцию и собирает обе программы. Он перезаписывает сгенерированные ассеты, поэтому художественные ручные правки следует хранить в отдельной ветке/копии. Не запускать старый `PrototypeBuilder.BuildDeliverables` для обновления этой ветки: он пересоздаёт исходную игровую сцену. Для одной игровой сборки использовать `ArtPackImporter.BuildGameplay`.

## Оставшиеся задачи

1. Ручная художественная доработка шести моделей, UV/LOD и анимации; проверка Humanoid для людей.
2. Лучник, отдельный налётчик, лошадь, всадник-разведчик и упряжь обоза.
3. Модульная крепость, казарма, лесопилка, мельница, склад и самостоятельная библиотека пропсов.
4. Доработка окружения под референс: текущие лес, река, мост и крепость остаются прототипными.
5. Профилирование полноценного сражения, уменьшение числа материалов/draw calls, оптимизация skinned-копий тел.

Ветка предназначена для ревью; автоматическое объединение с `main` не выполняется.
